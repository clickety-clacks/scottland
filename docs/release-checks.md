# Release checks

The `Scottland fast checks` workflow tests pull-request merge refs and merge-group refs for `main` and `0.3`. It builds the plugin and tools, runs locked Rust unit tests, and starts one isolated headless session on each architecture. Headless checks are preflight only; they do not establish physical GPU or real-session acceptance.

Register two repository or organization self-hosted runners with the labels `scottland-ci-x86_64` and `scottland-ci-aarch64`. Each runner must use a dedicated noninteractive account with `SCOTTLAND_CI_DEDICATED=1`, an existing owned `XDG_RUNTIME_DIR`, installed build and headless dependencies, and a checkout outside `/tmp`. The account must not own a live graphical session. The fast-check script refuses to start if those conditions fail and preserves scratch on uncertain cleanup. Keep the branch rules and merge queue disabled until both runner jobs complete successfully on a pull request and a merge-group ref. Public fork pull requests cannot execute on these self-hosted runners.

When `main` moves, open or update a PR from `main` to `0.3`. Resolve conflicts on a branch from the current `0.3` tip if a direct PR is not mergeable. Review the resolution on the opposite harness, run the fast checks against the current target tip, then use the merge queue. If `0.4` exists, repeat from `0.3` into `0.4`. Never force-push a release branch or infer a green result from its old tip. Until the queue is enabled, update to the target tip and rerun the same checks before an authorized merge.

Once `0.3` diverges, perform a full rehearsal after each forward merge and at least weekly while active, and again on the exact release-candidate tag before shipping. Record the exact commit and artifacts for install and reload from the version the daily machine runs, real-session behavior on an authorized test machine, and NVIDIA rendering on the designated hardware test machine. Use the shared runner's host audit and admission process; never run the rehearsal on the daily machine. A failed or incomplete rehearsal blocks the release candidate, not unrelated fast-check work.
